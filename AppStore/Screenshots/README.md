# App Store screenshots

Generated by `capture.sh` from a Debug build staged with `-screenshot <scene>`
(`Shut/App/ScreenshotStage.swift`). Re-run the script after any UI change.

| Folder | Pixels | App Store Connect slot | Ships with |
|---|---|---|---|
| `iPhone-6.9in` | 1320 × 2868 | iPhone 6.9" — the required one | v1.0 and v1.1 |
| `iPhone-6.5in` | 1284 × 2778 | iPhone 6.5" — optional while 6.9" is present | v1.0 and v1.1 |
| `iPad-13in` | 2064 × 2752 | iPad 13" — required once iPad is on | when iPad ships |
| `iPhone-Duo-cover` | 1398 × 2034 | iPhone Duo, outer display | v1.1 only |
| `iPhone-Duo-inner` | 2007 × 2853 | iPhone Duo | v1.1 only — not captured yet, see below |

The cover set has no editor shot: nobody edits on the outer display, and its
five faces already show the styles. The Duo's editor shot is in the inner set.

The iPhone sets use the lock copy ("Lock to begin", "You unlocked it."). That
is the v1.0 binary, and it is still what non-Duo phones see in v1.1. Nothing
fold-related appears in them, as `BUILD.md` requires for v1.0.

Order: 1 timer · 2 home · 3 grace · 4 kept · 5 history · 6 settings (the privacy statement, in the app) ·
7 appearance editor (Cute style, Colours tab). Everything but 7 is Classic.
Pro is on in the staged data so History shows week and month totals and the
editor shows no locks. Those are real Pro features, so the shots don't
overpromise; mark 5 and 7 as Pro in the captions.

## iPad: ready, not shipping yet

`iPad-13in` (2064 × 2752) is the size App Store Connect requires once the app
runs on iPad. The project still builds iPhone-only (`TARGETED_DEVICE_FAMILY =
1`), so App Store Connect won't take these until that becomes `1,2` — see
`DEFERRED.md`. `capture.sh` builds its own iPad-enabled copy to take them.

## Apple's rules these follow

From Apple's screenshot specs and asset guidance (checked 2026-10-27):

- 6.9" (1320 × 2868) satisfies the iPhone requirement; 6.5" is only required
  when 6.9" is missing. Up to 10 per size; the first three show in search.
- **No prices** in any image — staged launches never load the store, so no
  "$" appears. Keep the design captions price-free too.
- **Show the app in use.** The old text-only privacy card is gone; #6 is the
  real Settings screen with the privacy statement in it.
- **Duo screenshots add an "optimized for iPhone Duo" badge** to the product
  page. Upload them only with the build that has the fold (v1.1), or the badge
  promises something v1.0 doesn't do. Apple requires Duo shots from April 2027
  for apps built with the iOS 27.1 SDK.

## The Duo inner display needs one manual step

`simctl` can't change the Duo's pose, and the simulator boots shut. So the
cover display can be captured headlessly, but the inner display can't:

1. Open Device Hub (`Xcode-beta.app/Contents/Applications/DeviceHub.app`) and
   set the iPhone Duo to **open**.
2. Run `AppStore/Screenshots/capture.sh duo-inner`.

That writes home, grace, kept, history, settings and appearance at
2007 × 2853 with the fold copy ("Fold to begin", "You opened it.").
